# Лаборатори №3: Чанарын сценарио → SLO → k6 threshold

## 1. Performance — Сагсанд нэмэх

| Хэсэг | Тодорхойлолт |
|---|---|
| Тойм | Хэрэглэгч барааг сагсандаа нэмэхэд систем хурдан хариулна. |
| Системийн төлөв | API ажиллаж байгаа, POST /cart/add хүсэлт хүлээн авахад бэлэн. |
| Орчны төлөв | Локал WSL2 орчин; 60 секундийн турш секундэд нийт 10 хүсэлт илгээнэ. k6-д урьдчилан 10 VU хуваарилж, шаардлагатай бол 20 VU хүртэл ашиглана. |
| Гадаад өдөөлт | Хэрэглэгч барааг сагсанд нэмэх POST /cart/add хүсэлт илгээнэ. |
| Шаардлагатай хариу | Сервер HTTP 200 болон {"ok":true,"items":1} буцаана. |
| Хэмжүүр | Тестийн хугацаанд хүсэлтийн хариу хугацааны p95 < 200 мс, p99 < 400 мс; HTTP 200 хариуны хувь ≥ 99%. |

## 2. Reliability — Төлбөрийн найдвартай байдал

| Хэсэг | Тодорхойлолт |
|---|---|
| Тойм | Хэрэглэгчийн төлбөрийн хүсэлт алдаа багатай боловсруулагдана. |
| Системийн төлөв | API ажиллаж байгаа; /pay нь хүсэлт бүрд ойролцоогоор 5% магадлалаар HTTP 500 буцаах туршилтын логиктой. |
| Орчны төлөв | Локал WSL2 орчин; 60 секундийн турш секундэд нийт 10 хүсэлт; урьдчилан 10 VU, дээд тал нь 20 VU. Зориуд сервер зогсоохгүй. |
| Гадаад өдөөлт | Хэрэглэгч хэвийн төлбөрийн үйлдэл хийж POST /pay хүсэлт илгээнэ. |
| Шаардлагатай хариу | Сервер HTTP 200 болон {"paid":true} буцаана. |
| Хэмжүүр | Тестийн хугацаанд error rate < 1%; HTTP 200 биш хариу болон холболтын алдааг бүтэлгүй хүсэлтэд тооцно. Нэмэлт хугацааны зорилт: p95 < 300 мс, p99 < 500 мс. |

## 3. Availability — Сервер эвдрэлийн дараа сэргэх

| Хэсэг | Тодорхойлолт |
|---|---|
| Тойм | Сервер гэнэт зогссон ч богино хугацаанд дахин үйлчилгээ үзүүлдэг болно. |
| Системийн төлөв | API эхэндээ ажиллаж байгаа; тусдаа терминалаас серверийг зогсоож, гараар дахин асаах боломжтой. |
| Орчны төлөв | Локал WSL2 орчин; 120 секундийн турш секундэд нэг POST /cart/add шалгах хүсэлт илгээнэ. Хүсэлт бүрийн timeout 1 секунд байна. |
| Гадаад өдөөлт | Тест эхэлснээс 30 секундийн дараа серверийн процессыг хүчээр зогсоож crash үүсгэнэ; 5 секундийн дараа дахин асаах командыг өгнө. |
| Шаардлагатай хариу | Дахин ассан сервер HTTP 200 буцааж эхэлнэ. Үүний дараах дараалсан 3 шалгах хүсэлт амжилттай байна. |
| Хэмжүүр | 120 секундийн ажиглалтын хугацаанд availability ≥ 95%, үүнийг HTTP 200 авсан шалгалт / нийт шалгалт × 100 гэж тооцно. Сэргэх хугацаа нь процессыг зогсоосон мөчөөс дахин анхны HTTP 200 авсан мөч хүртэл ≤ 10 секунд байна. Амжилттай хүсэлтүүдийн хугацаа p95 < 200 мс, p99 < 400 мс байна. |

## Сайн сценариогийн 5 шинж

| Шинж | Өөрийн шалгалт |
|---|---|
| Итгэмжтэй | Сагсанд нэмэх, төлбөр хийх, сервер зогсох нь бодит хэрэглээнд тохиолддог. |
| Үнэ цэнэтэй | Хүлээлт, төлбөрийн алдаа, үйлчилгээний тасалдлыг хэмжинэ. |
| Тодорхой | Endpoint, HTTP арга, өдөөлт, хүлээгдэх хариуг заасан. |
| Нарийн | Ачаалал, тестийн хугацаа, алдааны хувь, percentile болон сэргэх хугацааны хязгаарыг тоогоор заасан. |
| Ойлгомжтой | Сценарио бүрийг ижил 6 хэсэгтэй хүснэгтээр бичсэн. |
