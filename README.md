# Лаборатори №2 — Гүйцэтгэлийн хэмжүүрийг k6-аар хэмжих

**Хичээл:** F.CSA313 — Программ хангамжийн чанарын баталгаа ба тест  
**Оюутан:** Б. Мөнгөншагай  
**Оюутны код:** B232270013

## 1. Зорилго

`https://test.k6.io` дээр k6 ашиглан p90/p95 latency, throughput, error rate болон хүсэлтийн амжилтын хувийг хэмжиж, ачааллаас хамаарах өөрчлөлтийг ажиглав. Скрипт GET хүсэлт илгээж, эцсийн хариуны status 200 эсэхийг шалгаад `sleep(1)` ажиллуулдаг.

## 2. Файлууд ба үр дүнгийн эх сурвалж

- `script.js` — тогтмол VU, анхдагч тохиргоо 5 VU / 1 минут.
- `stages.js` — шаталсан ачаалал.
- `threshold-pass.js`, `threshold-fail.js` — SLO болон зориудын хатуу босго.
- `results/run-05vu.txt`, `run-30vu.txt`, `run-100vu.txt` — хүснэгтийн эх үр дүн.
- `results/stages.txt`, `threshold-pass.txt`, `threshold-fail.txt` — бусад туршилтын үр дүн.
- `results/latest-terminal.txt` — хэрэглэгчийн өмнө илгээсэн terminal бичлэг; хуучин 30 секундийн baseline болон өмнөх SLO туршилтуудыг агуулсан архив.
- `results/run-metadata.json` — хэмжилтүүдийн эх сурвалж, команд, хугацаа болон threshold үр дүн.
- `screenshots/` — 5 туршилтын үр дүнгийн зураг.
- `scripts/capture-results.ps1` — өмнөх хувилбарт хадгалсан output-ийг browser-д дүрслэхэд ашигласан туслах скрипт; одоогийн terminal screenshot-уудыг энэ скриптээр үүсгээгүй.

5/30/100 VU, PASS болон FAIL-ийн бүх үр дүнг хэрэглэгчийн хамгийн сүүлд илгээсэн terminal бичлэгээс авсан. Эх бичлэгийг [submitted-terminal.txt](results/submitted-terminal.txt)-д бүтнээр хадгалж, таван туршилтыг тусдаа output файлд ялгасан; зөвхөн мөрийн төгсгөлийн хоосон зайг цэвэрлэсэн. Stages нь өмнөх бодит туршилтын үр дүн. Өөр өөр цагт ажиллуулсан туршилтууд тул сүлжээ болон серверийн тухайн үеийн нөхцөл нөлөөлж болно.

$k6 = '.\.tools\k6-v2.2.0-windows-amd64\k6.exe'

## 4. Суурь хэмжилт

5 VU ачааллаар **1 минут** ажиллуулсан бодит baseline:

```powershell
& $k6 run --vus 5 --duration 1m script.js
```

[run-05vu.txt](results/run-05vu.txt)-д baseline **p95 = 297.43 ms**, p90 = **276.64 ms**, throughput = **7.418077 хүсэлт/сек** байна. Нийт **450** HTTP хүсэлтээс алдаа **0**, status 200 шалгалт **225/225** амжилттай. Эдгээр үзүүлэлтийг хэрэглэгчийн илгээсэн terminal үр дүнгээс авсан.

## 6. Stages туршилт

30 секундэд 5 VU, дараагийн 1 минутад 30 VU, дараагийн 30 секундэд 100 VU болгон өсгөж, сүүлийн 30 секундэд 0 VU болгож бууруулсан. Нийт төлөвлөсөн хугацаа **2 минут 30 секунд**.

```powershell
& $k6 run stages.js
```

[stages.txt](results/stages.txt): p90 = **230.12 ms**, p95 = **232.59 ms**, throughput = **46.993386 хүсэлт/сек**, error rate = **0.00%** (0/7080). Status 200 шалгалт **3540/3540** амжилттай. Бүх үе шатны нийлбэр summary тул тогтмол VU-ийн хүснэгтэд ашиглаагүй.

## 7. SLO / Threshold

Ачаалал багатай үеийн p95-ээс 50% хүртэл удаашрахыг зөвшөөрөх лабораторийн босго болгон baseline × 1.5-ыг сонгосон. Энэ нөөц нь гадаад сүлжээний хэлбэлзлийг тодорхой хэмжээнд зөвшөөрөхийн зэрэгцээ суурь хэмжилтээс мэдэгдэхүйц удааширсныг илрүүлэх зорилготой бөгөөд үйлдвэрлэлийн хэрэглэгчийн шаардлагаар баталгаажуулсан босго биш.

Одоогийн 1 минутын baseline-аас:

```text
SLO p95 = baseline p95 × 1.5
        = 297.43 ms × 1.5
        = 446.145 ms
```

```powershell
& $k6 run -e SLO_P95_MS=446.145 threshold-pass.js
& $k6 run threshold-fail.js
```

Хоёр threshold туршилт **30 VU, 1 минут** ажилласан.

| Туршилт | p90 (ms) | p95 (ms) | Throughput (http_reqs/s) | Error rate | HTTP хүсэлт | Latency threshold | Үр дүн |
|---|---:|---:|---:|---:|---:|---|---|
| PASS | 229.67 | 231.85 | 45.352875 | 0.00% | 2776 | p(95)<446.145 | PASS |
| FAIL | 230.5 | 232.57 | 45.401179 | 0.00% | 2780 | p(95)<50 | FAIL |

[PASS output](results/threshold-pass.txt): **231.85 < 446.145 ms**, latency threshold хангагдсан; **0.00% < 1%**, алдааны хувьтай холбоотой threshold мөн хангагдсан. SLO-оос p95 нь **214.295 ms** бага байна.

[FAIL output](results/threshold-fail.txt): **232.57 > 50 ms** учраас зориудаар хатуу latency threshold зөрчигдсөн. Error rate **0.00%** тул `rate<0.01` нөхцөл PASS хэвээр. `thresholds on metrics 'http_req_duration' have been crossed` гэсэн алдаа нь энэ туршилтад хүлээгдэж буй үр дүн. **50 ms** нь зөвхөн FAIL үзүүлэх босго юм.

Өмнөх үнэлгээний **411.86 × 1.5 = 617.79 ms** тооцоо тухайн хуучин baseline-д зөв байсан. Дараагийн 30 секундийн baseline-ийн **293.27 × 1.5 = 439.905 ms** тооцоо мөн архивт бий. Энэ тайлангийн одоогийн **1 минутын** baseline өөр учраас хэрэглэсэн SLO нь **446.145 ms**.

## 8. Хэмжсэн үзүүлэлтүүд

- **p90 / p95:** HTTP хүсэлтийн хугацааны 90 болон 95-р перцентиль.
- **Throughput:** секундэд бүртгэгдсэн HTTP хүсэлтийн тоо.
- **Error rate:** амжилтгүй HTTP хүсэлтийн хувь.
- **Availability:** энэ туршилтад хүсэлтийн амжилтын хувиар үнэлсэн. `100% − error rate` томъёогоор гурван VU түвшинд **100.00%**. Энэ нь урт хугацааны uptime-ийн баталгаа биш.

## 9. Дүгнэлт

1. Ижил 1 минутын хугацаатай 5/30/100 VU туршилтын p95 тус бүр **297.43 / 282.43 / 234.01 ms** байсан.
2. Ачаалал 5-аас 100 VU болоход throughput **7.418077 → 44.875174 → 150.632874 хүсэлт/сек** болж өссөн.
3. Энэ удаагийн хэмжилтэд p95 буурч, error rate бүх түвшинд **0.00%** байсан тул 100 VU хүртэл хэрэглэгчийн туршлага муудаж эхлэх цэг ажиглагдаагүй.
4. Туршилтууд өөр цагт ажилласан тул latency-ийн бууралтыг зөвхөн VU тоотой холбох боломжгүй бөгөөд сүлжээ, серверийн тухайн үеийн нөхцөл нөлөөлж болно.
5. Лекцийн latency ба throughput нь ялгаатай үзүүлэлт гэсэн ойлголтыг хариуны хугацааг p95-аар, хүсэлтийн урсгалыг секундэд ногдох HTTP хүсэлтийн тоогоор тусад нь хэмжиж бататгасан.
6. Status 200 шалгалтууд **100.00%** амжилттай, error rate **0.00%** байсан нь туршилтын хугацааны хүсэлтийн амжилтыг харуулсан боловч урт хугацааны availability-г батлахгүй.
7. Baseline p95-ээс 50% хүртэл удаашрахыг зөвшөөрч SLO-г **297.43 × 1.5 = 446.145 ms**, алдааны хувийн босгыг **1%-аас бага** гэж тогтоосон.
8. PASS туршилтад p95 **231.85 ms**, error rate **0.00%** байсан тул хоёр SLO нөхцөл хоёулаа хангагдсан.
9. Зориудаар хатуу **50 ms** босготой туршилтын p95 **232.57 ms** байсан тул HTTP хүсэлтүүд амжилттай байсан ч latency threshold FAIL болсон нь CI quality gate-ээр гүйцэтгэлийн шаардлага шалгах зарчмыг харуулсан.
10. Stages-ийн нийлбэр summary болон тусдаа VU хэмжилтүүдийн ялгааг харгалзан тайланг бодит output, terminal screenshot-оор нотолсон бөгөөд эдгээр туршилтаар системийн дээд хүчин чадлыг тогтоогоогүй.
