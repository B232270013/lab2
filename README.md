# Лаборатори №2 — Гүйцэтгэлийн хэмжүүрийг k6-аар хэмжих

**Хичээл:** F.CSA313 — Программ хангамжийн чанарын баталгаа ба тест  
**Оюутан:** Б. Мөнгөншагай

## 1. Зорилго

`https://test.k6.io` дээр k6 ашиглан p90/p95 latency, throughput, error rate болон хүсэлтийн амжилтын хувийг хэмжиж, ачааллаас хамаарах өөрчлөлтийг ажиглав. Скрипт GET хүсэлт илгээж, эцсийн хариуны status 200 эсэхийг шалгаад `sleep(1)` ажиллуулдаг.

## 2. Файлууд ба үр дүнгийн эх сурвалж

- `script.js` — тогтмол VU, анхдагч тохиргоо 5 VU / 1 минут.
- `stages.js` — шаталсан ачаалал.
- `threshold-pass.js`, `threshold-fail.js` — SLO болон зориудын хатуу босго.
- `results/run-05vu.txt`, `run-30vu.txt`, `run-100vu.txt` — хүснэгтийн эх үр дүн.
- `results/stages.txt`, `threshold-pass.txt`, `threshold-fail.txt` — бусад туршилтын үр дүн.
- `results/latest-terminal.txt` — хэрэглэгчийн өмнө илгээсэн terminal бичлэг; хуучин 30 секундийн baseline болон өмнөх SLO туршилтуудыг агуулсан архив.
- `results/run-metadata.json` — хэмжилтүүдийн эх сурвалж, команд, хугацаа болон дахин ажиллуулсан PASS-ийн exit code.
- `screenshots/` — 5 туршилтын үр дүнгийн зураг.
- `scripts/capture-results.ps1` — хадгалсан 5/30/100 VU болон PASS output-ийг browser-д нээж screenshot авах скрипт.

5/30/100 VU-ийн үзүүлэлтүүдийг хэрэглэгчийн хамгийн сүүлд илгээсэн 1 минутын terminal үр дүнгээс авсан. Тусдаа output файлуудад хэмжилтийн мөрүүдийг хадгалж, лого болон Markdown форматлалтыг хассан. PASS-ийг шинэ baseline-аас тооцсон босгоор энэ засварын үеэр дахин ажиллуулсан. Stages болон FAIL нь өмнөх бодит туршилтын үр дүн. Өөр өөр цагт ажиллуулсан туршилтууд тул сүлжээ болон серверийн тухайн үеийн нөхцөл нөлөөлж болно.

## 4. Суурь хэмжилт

5 VU ачааллаар **1 минут** ажиллуулсан бодит baseline:

```powershell
& $k6 run --vus 5 --duration 1m script.js
```

[run-05vu.txt](results/run-05vu.txt)-д baseline **p95 = 297.43 ms**, p90 = **276.64 ms**, throughput = **7.418077 хүсэлт/сек** байна. Нийт **450** HTTP хүсэлтээс алдаа **0**, status 200 шалгалт **225/225** амжилттай. Эдгээр үзүүлэлтийг хэрэглэгчийн илгээсэн terminal үр дүнгээс авсан.

| VU | Хугацаа | p90 (ms) | p95 (ms) | Throughput (http_reqs/s) | Error rate |
|---:|---:|---:|---:|---:|---:|
| 5 | 1m | 276.64 | 297.43 | 7.418077 | 0.00% |
| 30 | 1m | 274.99 | 282.43 | 44.875174 | 0.00% |
| 100 | 1m | 231.23 | 234.01 | 150.632874 | 0.00% |

Эх сурвалж: [5 VU](results/run-05vu.txt), [30 VU](results/run-30vu.txt), [100 VU](results/run-100vu.txt). p90/p95 нь `http_req_duration`, throughput нь `http_reqs` мөрийн `/s`, error rate нь `http_req_failed` утга. Амжилтгүй HTTP хүсэлт тус бүр **0/450, 0/2700, 0/9230** байсан.


## 7. SLO / Threshold

Одоогийн 1 минутын baseline-аас:

```text
SLO p95 = baseline p95 × 1.5
        = 297.43 ms × 1.5
        = 446.145 ms
```

```powershell
& $k6 run --no-color --quiet -e SLO_P95_MS=446.145 threshold-pass.js
& $k6 run threshold-fail.js
```

Хоёр threshold туршилт **30 VU, 1 минут** ажилласан.

| Туршилт | p90 (ms) | p95 (ms) | Throughput (http_reqs/s) | Error rate | HTTP хүсэлт | Latency threshold | Үр дүн |
|---|---:|---:|---:|---:|---:|---|---|
| PASS | 231.98 | 235.78 | 45.214701 | 0.00% | 2760 | p(95)<446.145 | PASS |
| FAIL | 270.55 | 276.29 | 45.255594 | 0.00% | 2760 | p(95)<50 | FAIL |

[PASS output](results/threshold-pass.txt): **235.78 < 446.145 ms**, latency threshold хангагдсан; **0.00% < 1%**, алдааны хувьтай холбоотой threshold мөн хангагдсан. Exit code **0**. SLO-оос p95 нь **210.365 ms** бага байна.

[FAIL output](results/threshold-fail.txt): **276.29 > 50 ms** учраас зориудаар хатуу latency threshold зөрчигдсөн. Error rate **0.00%** тул `rate<0.01` нөхцөл PASS хэвээр. `thresholds on metrics 'http_req_duration' have been crossed` гэсэн алдаа нь энэ туршилтад хүлээгдэж буй үр дүн. **50 ms** нь зөвхөн FAIL үзүүлэх босго юм.

Өмнөх үнэлгээний **411.86 × 1.5 = 617.79 ms** тооцоо тухайн хуучин baseline-д зөв байсан. Дараагийн 30 секундийн baseline-ийн **293.27 × 1.5 = 439.905 ms** тооцоо мөн архивт бий. Энэ тайлангийн одоогийн **1 минутын** baseline өөр учраас хэрэглэсэн SLO нь **446.145 ms**.

## 8. Хэмжсэн үзүүлэлтүүд

- **p90 / p95:** HTTP хүсэлтийн хугацааны 90 болон 95-р перцентиль.
- **Throughput:** секундэд бүртгэгдсэн HTTP хүсэлтийн тоо.
- **Error rate:** амжилтгүй HTTP хүсэлтийн хувь.
- **Availability:** энэ туршилтад хүсэлтийн амжилтын хувиар үнэлсэн. `100% − error rate` томъёогоор гурван VU түвшинд **100.00%**. Энэ нь урт хугацааны uptime-ийн баталгаа биш.

## 9. Дүгнэлт

1. Ижил 1 минутын хугацаатай 5/30/100 VU туршилтын p95 тус бүр **297.43 / 282.43 / 234.01 ms** байсан.
2. 30 VU-ийн p95 baseline-ээс **15.00 ms** бага; 100 VU-ийн p95 нь 30 VU-ээс **48.42 ms** бага байв.
3. Throughput **7.418077 → 44.875174 → 150.632874 хүсэлт/сек** болж өссөн. Энэ хэмжилтэд p95 нь 297.43 → 282.43 → 234.01 ms болж буурсан.
4. Бүх түвшинд error rate **0.00%**, status 200 шалгалтууд **100.00%** амжилттай байсан.
5. Энэ удаагийн гурван хэмжилтэд VU нэмэгдэхэд p95 буурсан. Туршилтууд өөр цагт ажилласан тул ялгааг зөвхөн VU тоогоор тайлбарлахгүй; сүлжээ болон серверийн нөхцөл нөлөөлж болно.
6. Baseline-аас **297.43 × 1.5 = 446.145 ms** SLO гаргасан. Тусдаа PASS туршилтын p95 **235.78 ms** тул шинэ SLO бодитоор хангагдсан.
7. Зориудаар хатуу **50 ms** босго тавихад p95 **276.29 ms** байсан тул HTTP хүсэлтүүд амжилттай байсан ч latency threshold FAIL болсон.
8. Хүснэгт, threshold үр дүн болон таван зураг нь холбогдох output файлуудтай тохирно. Эдгээр туршилт нь системийн дээд хүчин чадлыг тогтоохгүй.
